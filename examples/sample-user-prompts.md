# 麦门省钱助手：演示案例与用户提示词

## 案例一：查询附近门店

**用户提示词**

我在上海人民广场附近，帮我查询周边麦当劳门店，优先推荐距离近的门店。

**预期处理流程**

1. 调用附近门店查询工具。
2. 展示实际返回的门店名称、距离及可用信息。
3. 让用户选择目标门店，再查询该门店的餐品。

**验证要求**

门店名称、距离和门店标识必须来自真实工具返回结果。不得将历史测试结果直接当作实时结果。

## 案例二：预算内选择餐品

**用户提示词**

我的预算是 40 元，请根据查询到的菜单帮我搭配餐品，尽量接近预算，但不要超支。

**预期处理流程**

1. 查询目标门店的实际餐品及价格。
2. 将实际查询结果转换为组合计算器需要的数据格式。
3. 使用 `scripts/combo_optimizer.py` 计算符合预算的组合。
4. 展示餐品明细、合计金额及剩余预算。

**验证要求**

本地组合算法只负责计算输入数据。若输入价格不是实时查询所得，必须明确标注为演示数据，不能宣称推荐组合已通过实时菜单验证。

## 案例三：核验餐品价格

**用户提示词**

请帮我核对这款餐品的菜单价格和价格计算结果是否一致。

**预期处理流程**

1. 查询目标门店的餐品价格。
2. 按实际工具定义调用价格计算工具。
3. 统一金额单位。
4. 展示菜单价格、计价结果和核验结论。

**历史验证记录**

在一次真实测试中，餐品 `9900005456` 的查询价格为 33.5 元，价格计算结果为 3350 分，换算后为 33.50 元，两者一致。

以上是历史测试记录，不代表该餐品当前在所有门店均以此价格供应。

## 案例四：查询优惠

**用户提示词**

请帮我查询目前可用的优惠，并确认这些优惠是否真的能降低我的餐品价格。

**预期处理流程**

1. 查询实际可用的优惠信息。
2. 区分优惠信息查询结果与计价结果。
3. 如果缺少必要的优惠标识或参数，明确说明当前无法核验优惠是否生效。
4. 不将未成功核验的优惠计算为确定节省金额。

**验证要求**

只有工具返回的计价结果能够证明优惠已生效时，才能明确说明折扣已计入价格。

## 案例五：查询营养信息

**用户提示词**

请帮我查询这款餐品的营养信息，并说明数据是否与我选的商品完全匹配。

**预期处理流程**

1. 查询营养数据。
2. 核对餐品名称及规格。
3. 只有在匹配可靠时才展示营养数据。
4. 对无法确认的匹配关系明确提示，不将单品数据当作套餐总营养值。

## 演示边界

本项目目前由 MCP 查询工具、价格核验流程和本地预算组合计算器组成。上述案例描述的是使用场景及预期流程，不代表每个案例都已完成端到端自动化验证。

项目不自动创建或取消订单，也不将演示数据冒充实时数据。
